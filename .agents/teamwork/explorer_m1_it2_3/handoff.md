## 2. Logic Chain

1. **Observation 1** proves that emitting `module.exports` into a `.js` file inside a `"type": "module"` package violates the Node.js ESM module specification and causes runtime `ReferenceError` crashes.
2. Because Metro bundler resolves `webAppHtml.js` prior to `webAppHtml.ts` (per default `sourceExts`), an invalid `webAppHtml.js` breaks or destabilizes mobile bundling and external loaders.
3. Therefore, changing `scripts/generate-mobile-bundle.js` lines 180–185 to emit `export const webAppHtml = ${escapedHtml};\nexport default webAppHtml;\n` produces a pure ES module compatible with both named imports (`import { webAppHtml } from ...` in `App.tsx`), default imports, and Node ESM loaders.
4. **Observation 2** proves that the previous 100% pass rate in Milestone 1 feature tests was artificial because F01, F02, F03, and F04 evaluated synthetic in-memory strings and dummy objects rather than the real files on disk.
5. **Observation 3 and Observation 4** demonstrate that when real files are inspected, `App.tsx` fails TypeScript syntax parsing (lines 38-39) and `metro.config.js` fails Node module resolution (line 1).
6. Therefore, updating `tests/e2e/tier1-features.test.cjs` to directly assert against `path.join(PROJECT_ROOT, "App.tsx")`, `metro.config.js`, `app.json`, and `index.js` (including AST syntax validation via `typescript.createSourceFile`) transforms the test suite into an authentic verification oracle that reliably catches syntax defects and runtime crashes.
